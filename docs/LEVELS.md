# Карты, объекты и свет

В `config/settings.py` выберите `LEVEL_NAME`: `maze`, `corridor`, `stairs` или `demo`. Изменения карт и настроек подхватываются после перезапуска.

Основная карта - [resources/levels/maze.json](../resources/levels/maze.json). `corridor.tmx` редактируется в Tiled; `stairs` и `demo` собираются кодом в `game/levels/`.

## Лабиринт

В `floors` лежат две сетки: `#` - стена, `.` - проход. Размеры обоих этажей должны совпадать. Координата клетки записывается как `[этаж, строка, столбец]`, начиная с нуля. Высота в мире идёт по Y, пол - по XZ.

| Поле | Что меняет |
| --- | --- |
| `cell_size` | Размер клетки в метрах |
| `floor_height`, `wall_height`, `slab_thickness` | Высоту этажа, стен и перекрытия; последние два значения в сумме дают первое |
| `floor_materials`, `wall_materials` | Материалы полов и стен |
| `spawn`, `exit` | Клетки старта и выхода; выход находится на северной границе второго этажа |
| `stairs` | Связи этажей через западную или восточную границу; клетки входов должны быть проходами |
| `stair_steps`, `stair_run`, `stair_width` | Количество, глубину и ширину ступеней |
| `wing_width` | Ширину лестничной клетки |

Подвал описан отдельно, в `basement`. `depth` задаёт глубину, `entry` - клетку входа первого этажа на западной границе, `lower_row` - строку нижней площадки. Чтобы убрать подвал, удалите этот раздел и закройте его вход в сетке.

`basement.lamp_columns` и `lamp_rows` задают сетку ламп, `lamp_margin` - отступ от стен. Сейчас это зал с сеткой 15x15; внизу у входа стоят три коробки. Выход из лабиринта находится на верхнем этаже и ведёт на балкон.

## Блоки и материалы

Коробки подвала находятся в `basement.boxes`:

```json
{
  "position": [-25.0, 0.35, 13.8],
  "size": [1.5, 0.7, 1.5],
  "material": "wood",
  "interaction": {
    "name": "Wooden crate",
    "action": "Inspect",
    "message": "The lid is nailed shut."
  }
}
```

`position` - центр блока: XZ мировые, Y отсчитывается от пола подвала. `size` - размеры XYZ. Необязательный `interaction` добавляет осмотр на E; стены перекрывают доступ, дальность задаёт `INTERACTION_REACH`.

Текстуры лежат в `resources/textures/`. Их имена и размер повторения задаёт `MATERIAL_TEXTURES` в настройках. Готовые материалы: `asphalt`, `dirty_tiles`, `wood`, `concrete`, `plaster`, `hospital_tiles`, `brick`, `rust`. [Подробнее о текстурах](../resources/textures/README.md).

## Двери и ключи

Добавляются в корневой массив `objects`:

```json
[
  {
    "id": "basement_key", "type": "key", "name": "Basement key",
    "key_id": "basement", "node": [0, 19, 1], "offset": [0.75, 0, -1]
  },
  {
    "id": "basement_door", "type": "door", "name": "Basement door",
    "key_id": "basement", "node": [0, 19, 0], "offset": [1.5, 0, 0],
    "axis": "z", "width": 1.8, "height": 2.35, "thickness": 0.18,
    "open_seconds": 0.9, "hinge_side": "left", "open_angle": -90
  }
]
```

`id` должен быть уникальным. Одинаковый `key_id` связывает ключ с дверью; ключ не расходуется. `node` указывает открытую клетку, `offset` смещает объект от её центра на уровне пола.

`axis` - ось ширины двери (`x` или `z`), толщина идёт по другой горизонтальной оси. `hinge_side` выбирает край петли вдоль ширины: `left` - меньшая координата, `right` - большая. `open_angle` задаёт угол вокруг Y со знаком, от 10 до 110 градусов по модулю. Знак меняет сторону открытия. `open_seconds` - время поворота.

Оставьте место для всей дуги движения: стены сами не вырезаются. Открытая дверь остаётся видимой и твёрдой. Если игрок мешает открыванию, она подождёт. Закрывание пока не добавлено.

Ключ со стойкой и дверь с рамой собираются в `game/levels/objects.py`. Состояния объектов и поворот блоков находятся в движке, подбор ключа и проверка замка - в `game/interactions.py` и `game/inventory.py`.

## Враг

В подвале патрулирует фигура с красными глазами. Она замечает игрока в поле зрения, идёт к нему и некоторое время помнит последнюю видимую позицию. Стены и закрытая дверь перекрывают зрение и движение. Урона, смерти и боя пока нет; возле игрока враг останавливается. Автоматического поиска пути вокруг сложных препятствий пока тоже нет, поэтому маршрут лучше прокладывать по открытому залу.

В `objects` можно добавить:

```json
{
  "id": "basement_watcher",
  "type": "enemy",
  "position": [-21, -3.6, 16.5],
  "patrol": [[-21, -3.6, 16.5], [-17, -3.6, 16.5], [-17, -3.6, 9.5]],
  "settings": {"patrol_speed": 1.0, "chase_speed": 1.9, "sight_range": 10}
}
```

`position` задаёт мировые координаты ног. Вместо неё можно использовать `node` и `offset`, как у остальных объектов. Точки `patrol` всегда мировые и должны лежать на одном этаже со стартом врага. Без маршрута он стоит на месте, пока не заметит игрока. Начальное направление взгляда совпадает с направлением к первой следующей точке, а без маршрута это -Z.

Общие параметры находятся в `ENEMY_*`, `ENEMIES_ENABLED = False` убирает врагов. В `settings` объекта можно переопределить `patrol_speed`, `chase_speed`, `sight_range`, `view_angle`, `memory_seconds`, `vision_interval`, `stop_distance`, `radius`, `height`. Положение ног и столкновения рассчитывает `CharacterBody`; состояние ИИ видно в F3.

Пока фигура собрана из блоков. Она получает освещение потолочных ламп, но отбрасывает тень только от фонарика: её движение не вызывает перезапекание теней неподвижных ламп.

## Лампы

Раздел `lighting` содержит фоновый свет `ambient`, стили `presets` и список `lamps`. Пример лампы:

```json
{
  "node": [0, 19, 1],
  "style": "cold",
  "flicker": {"interval": 8.0, "duration": 0.7, "minimum": 0.3, "seed": 19}
}
```

Вместо `node` можно указать мировую `position`. У стиля есть `color`, `intensity` и `radius`. По клетке светильник ставится под потолком. `shadow_resolution` принимает 64, 128 или 256; удвоение разрешения требует вчетверо больше памяти для теней.

`flicker` необязателен и может быть общим для стиля. `interval` - период, `duration` - длительность сбоя, `minimum` - минимальная яркость от 0 до 1, `seed` - сдвиг фазы. Длительность должна быть меньше периода. `flicker: null` у лампы отключает мерцание стиля.

В подвале используются `lamp_color`, `lamp_intensity`, `lamp_radius`. `flickering_lamps` принимает `"all"` или список номеров `строка * lamp_columns + столбец`; параметры мерцания лежат в `basement.flicker`. Общее отключение - `LIGHT_FLICKER_ENABLED = False` в настройках.

Движок поддерживает до 512 ламп уровня и 16 подвижных спотов. Лампы передаются в шейдер через текстуру данных; сетка пространства выбирает подходящие источники для каждой области. Карты теней ламп готовятся при загрузке. При движении двери обновляются только затронутые лампы, а мерцание меняет яркость без пересчёта теней.

Фонарик управляется через `FLASHLIGHT_*` в настройках. Внутренний и внешний углы задают половину конуса; внутренний должен быть меньше внешнего. `DYNAMIC_SHADOW_RESOLUTION` принимает 128, 256, 512 или 1024. У подвижных источников тени обновляются при изменении положения, направления или геометрии. Модели фонарика и объёмного луча пока нет.

## Туман, снег и цвет

Всё находится в `config/settings.py`:

- `FOG_ENABLED`, `FOG_COLOR`, `FOG_START`, `FOG_END` - туман по расстоянию от камеры. Между началом и концом поверхность плавно растворяется в цвете фона.
- `SNOW_ENABLED`, `SNOW_COUNT`, `SNOW_FALL_SPEED`, `SNOW_FLAKE_SIZE` - снег. В `maze` он отключён самим уровнем; для него подойдут `corridor`, `stairs` и `demo`.
- `POSTPROCESS_ENABLED`, `COLD_STRENGTH`, `COLD_TINT`, `COLD_SATURATION` - холодный оттенок и насыщенность.
- `BLOOM_STRENGTH`, `BLOOM_THRESHOLD`, `BLOOM_COLOR`, `BLOOM_RADIUS` - свечение. Сила 0 отключает его, сохраняя цветокоррекцию.

Туман не создаёт объёмные лучи. Полностью скрытые им пиксели пропускают расчёт освещения, но геометрия всё ещё рисуется в глубину. HUD выводится после эффектов. Рендер использует отсечение по камере и предварительный проход глубины; они уменьшают работу с невидимыми поверхностями.
