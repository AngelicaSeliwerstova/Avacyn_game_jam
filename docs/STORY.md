# Как редактировать сюжет

Игра читает сценарий из **`resources/story/hospital/`**. Реплики, задачи, порядок
событий и условия запуска сцен меняются без редактирования Python.

| Файл | Содержимое |
| --- | --- |
| `campaign.json` | Список и доступность актов, персонажи, начальные точки кампании |
| `acts/act0/dialogue.json` | Диалоги начального акта 1 «Под софитами» (ID `act0`) |
| `acts/act0/act.json` | Сцены, задачи, зоны, условия, переходы |
| `acts/act0/documents.json` | Письмо, подписи плана, правила чтения |
| `acts/act1/dialogue.json` | Акт 2: пропажа кулона, охрана, архив, узнавание украшения |
| `acts/act1/act.json` | Шкаф потерянных вещей, восстановление записи, завершение акта 2 |
| `acts/act2/dialogue.json` | Акт 3: подруга, признание, решение принять помощь |
| `acts/act2/act.json` | Тело и кулон, вид от первого лица, светлая больница, закрытие палаты 313 |
| `resources/puzzles/cctv/archive.json` | Порядок кадров, подписи, звуки и последовательность записи |

`docs/SCENARIO.md` — полный актуальный литературный сценарий; игра его не читает.
Технические ID `act0`, `act1`, `act2` соответствуют актам 1, 2, 3. Кнопка
«Продолжить» связывает главы. Карта `healed` сохраняет место героини после
принятия помощи и открывает финальный путь в палату 313.
Сохраняйте JSON в UTF-8 и перезапускайте игру после редактирования. Текущая сцена
использует уже загруженные данные, прогресс хранится в памяти до перезапуска.
В JSON нельзя добавлять комментарии или лишнюю запятую после последнего элемента.

## Реплики и выборы

В `dialogue.json` каждый именованный разговор — список реплик:

```json
{
  "meeting": [
    {"speaker": "hero", "text": "Здравствуйте. Это мой кабинет?"},
    {"speaker": "doctor", "text": "Давай сначала поговорим."}
  ]
}
```

Это пример структуры: в настоящем файле сохраните остальные разговоры.
Можно добавлять, удалять и переставлять реплики. `speaker` — ID персонажа,
его имя задаётся в `campaign.json` → `characters` → `name`.
Длинные реплики автоматически делятся на несколько экранов.

Реплики появляются по буквам с голосовыми пиканиями, без речевой озвучки. Первое E / Enter
раскрывает текущую реплику целиком, второе продолжает разговор.
В `campaign.json` старое поле `voice` сохраняется для совместимости:

```json
"voice": {"pitch_hz": 820, "pitch_variation": 0.08, "volume": 0.7, "chars_per_second": 38}
```

`chars_per_second` задаёт скорость текста (5–120), `pitch_hz` — высоту пиканий,
`pitch_variation` — её вариацию, `volume` — громкость. Пикания включены через
`DIALOGUE_BEEPS_ENABLED`; синтезированная речь не воспроизводится.

Между репликами можно вставить выбор:

```json
{
  "choice": "trust_doctor",
  "speaker": "hero",
  "prompt": "Что ответить?",
  "options": [
    {
      "label": "Довериться врачу",
      "set_flags": ["trusted_doctor"],
      "lines": [
        {"speaker": "hero", "text": "Хорошо. Я пойду с вами."},
        {"speaker": "doctor", "text": "Я рядом."}
      ]
    },
    {
      "label": "Попросить объяснений",
      "lines": [{"speaker": "hero", "text": "Сначала объясните, что происходит."}]
    }
  ]
}
```

Допустимо 1–4 варианта. В `lines` можно вложить следующий выбор.
`label` делайте коротким: это подпись кнопки; полную реплику пишите в `lines`.
После ветки разговор продолжается со следующего общего элемента списка.
Ответ запоминается как `act0:choice:trust_doctor:0` (варианты нумеруются с нуля).
Необязательный `set_flags` позволяет учитывать ответ в последующих сценах.

## Сцены и задачи

В `act.json` сцена состоит из ID, условия запуска (`trigger`) и действий (`steps`):

```json
{
  "id": "meet_doctor",
  "levels": ["peaceful"],
  "unless": ["doctor_met"],
  "trigger": {"type": "talk", "actor": "doctor"},
  "steps": [
    {"type": "dialogue", "id": "meeting"},
    {"type": "flags", "add": ["doctor_met"]},
    {"type": "follow", "actor": "doctor", "enabled": true}
  ]
}
```

Сцены проверяются сверху вниз, запускается первая подходящая. Пока идёт диалог,
чтение документа или эффект, другие сцены не запускаются.

| Поле | Значение |
| --- | --- |
| `levels` | Только перечисленные карты; без поля — любая карта кампании |
| `requires` | Все перечисленные флаги должны быть установлены |
| `unless` | Ни один из перечисленных флагов не должен быть установлен |
| `once` | По умолчанию `true`; `false` разрешает повторный запуск сцены |
| `cooldown` | Минимальная пауза между запусками сцены, секунды |

В `objectives` задаются задачи с `title` и `description`. Игра показывает первую
задачу, подходящую по `levels`, `requires`, `unless`. Последняя задача без условий
может служить вариантом по умолчанию. Не переименовывайте ID сцен и флаги посреди
прохождения; после таких изменений начинайте новую игру.

## Условия запуска

| `trigger` | Когда срабатывает |
| --- | --- |
| `{"type":"load"}` | Загрузка карты или начало следующего акта |
| `{"type":"talk","actor":"doctor"}` | Взаимодействие с персонажем |
| `{"type":"interact","object":"mother_letter"}` | Взаимодействие с документом на карте |
| `{"type":"zone","zone":"office"}` | Нахождение в зоне |
| `{"type":"zone_enter","zone":"office"}` | Момент входа в зону |
| `{"type":"outside_zone","zone":"reception"}` | Нахождение снаружи зоны |
| `{"type":"idle","seconds":18}` | Игрок стоит указанное время |
| `{"type":"revisit","zones":["office"]}` | Повторный вход в одну из зон |
| `{"type":"event","name":"stairs_walk_finished"}` | Завершён проход по лестнице и затихла тряска |
| `{"any":[ ... ]}` | Любое из вложенных условий |

Зоны находятся в `zones` текущего акта. `min` и `max` — углы объёма `[X,Y,Z]`,
где Y — высота. Например: `"office": {"min":[-20.7,-0.5,-13.9],"max":[-14.3,0.5,-8.3]}`.
Для `outside_zone` обязательно задавайте нужные флаги: это нахождение снаружи,
а не только момент выхода. Для повторных подсказок используйте `once: false` и `cooldown`.

`event` ожидает именованный сигнал от игровых механик. Сигнал остаётся в очереди,
пока не запустится подходящая сцена, поэтому он не теряется во время разговора.
В новой начальной главе `rusty_nail` срабатывает один раз в зоне повреждённых перил после получения ключа. Это звук и подпись `say`, без диалога или смены задания. Старый отдельный акт использует `stairs_walk_finished`.

## Действия

| Элемент `steps` | Результат |
| --- | --- |
| `{"type":"dialogue","id":"meeting"}` | Разговор из `dialogue.json` этого акта |
| `{"type":"flags","add":["met"],"remove":["waiting"]}` | Установить / убрать флаги |
| `{"type":"title","title":"АКТ 1","text":"Название","seconds":4,"fade_seconds":1.2}` | Титр с исчезновением |
| `{"type":"effect","effect":"interference","seconds":3.6}` | Помехи и затемнение; также доступен `blackout` |
| `{"type":"level","level":"start","preserve_scene":true}` | Переход на карту с сохранением позиций и состояний общих объектов |
| `{"type":"follow","actor":"doctor","enabled":true}` | Включить сопровождение; `false` останавливает его |
| `{"type":"map","id":"hospital_plan"}` | Открыть план |
| `{"type":"document","id":"mother_letter"}` | Открыть документ |
| `{"type":"archive"}` | Открыть архив документов за разные годы; `case: true` возвращает к делу №081 после чтения |
| `{"type":"audio","file":"act0/monster_growl.wav","volume":0.65}` | Проиграть сценарный WAV из `resources/audio` |
| `{"type":"voiceover","id":"cradle_memory"}` | Автоматическое воспроизведение записанных голосов и субтитров без кнопки пропуска |
| `{"type":"focus_camera","position":[-13.2,6.65,-17.8],"target":[-16,5.6,-20.5]}` | Удерживать заданный ракурс, в том числе во время пауз |
| `{"type":"release_camera"}` | Освободить сюжетную камеру перед возвращением управления |
| `{"type":"first_person","enabled":true}` | Переключить финальную сцену на вид от первого лица |
| `{"type":"offer_help"}` | Поставить героиню и доктора у лестницы и протянуть руку |
| `{"type":"clear_event","name":"closed:f3_patient_ward_313"}` | Сбросить старое закрытие двери перед финальным взаимодействием |
| `{"type":"ambience","gain":0.03,"seconds":1.2}` | Плавно изменить громкость больницы; не влияет на записанные голоса |
| `{"type":"grant_key","id":"second_floor_key","name":"Ключ от второго этажа"}` | Добавить ключ в инвентарь |
| `{"type":"effect","effect":"distortion","seconds":1.2}` | Лёгкое искажение поверх видимой сцены |
| `{"type":"say","speaker":"doctor","text":"Я рядом.","seconds":5.5}` | Подсказка без остановки игры |
| `{"type":"sound","profile":"doctor","volume":[0.13,0.24]}` | Звук шагов; `doctor` / `player`, громкость слева и справа 0–1 |
| `{"type":"complete_act"}` | Установить `complete_flag` текущего акта |
| `{"type":"next_act"}` | Запустить включённый `next_act`, если текущий акт завершён |
| `{"type":"dialogue","id":"memory","presentation":"memory"}` | Реплики воспоминания с приглушённым тёплым фоном |
| `{"type":"object_state","object":"f3_ward_306_tv","state":"memory"}` | Изменить состояние физического предмета |
| `{"type":"wait","seconds":1}` | Пауза с блокировкой управления; мир продолжает обновляться |
| `{"type":"wait_object","object":"f3_patient_ward_313","state":"open"}` | Дождаться окончания анимации предмета с блокировкой управления |
| `{"type":"effect","effect":"fade_to_black","seconds":1.5}` | Плавно затемнить изображение |
| `{"type":"end","title":"КОНЕЦ АКТА 1","text":"Название"}` | Чёрный финальный экран с перезапуском и выходом |
| `{"type":"puzzle","id":"cctv_archive"}` | Открыть отдельный режим видеорегистратора; повторный вход после решения сразу запускает запись |
| `{"type":"puzzle_checkpoint","id":"cctv_archive"}` | Сохранить, что разговор после записи завершён |

Если у завершённого акта включён `next_act`, экран `end` предлагает «Продолжить».
При переходе положение персонажей и открытые двери остаются прежними.
Головоломки перечисляются в `campaign.json` → `puzzles`, пути задаются относительно
`resources/puzzles`. Событие `watched:cctv_archive` запускает разговор после полного
просмотра; Esc не отмечает прерванную запись просмотренной.

`level` должен быть последним действием сцены. Продолжение на другой карте
задаётся её сценой `load`. `preserve_scene: true` подходит для превращения одного
здания с общей геометрией. Для другой локации используйте `false`: появление будет
в её стартовой точке. Новая механика, например головоломка, потребует нового
действия в коде; сочетания существующих действий меняются в JSON.

## Документы и планы

У каждого документа в `documents.json` уникальный во всей кампании ID, `type`,
`title` и `read_flag`. Для обычного документа `pages` — список текстов страниц.
Переносы записываются как `\n`, пустая строка — `\n\n`. Длинные страницы делятся
на дополнительные экраны автоматически.

`require_last_page: true` запрещает закрывать документ до последней страницы.
Для плана аналогичное правило — `require_all_floors: true`. После первого закрытия
устанавливается `read_flag`, предмет добавляется в инвентарь и выполняется
`on_first_read` — такой же список действий, как `steps`. При перечитывании он не
повторяется. Так устроен разговор после прочтения письма из папки за 1981 год. План необязателен. Закрытие каждого обязательного
документа допускается после просмотра последней страницы. Архив возвращается
к папке после разговора, не открывая письмо автоматически.

У плана `floors` — список этажей, на каждом подписи `[X,Z,"Текст"]`. Стены берутся
из геометрии карты. `stair` — `[X,Z,радиус]`, `highlights` — выделенные подписи,
`hint` и `first_hint` — пояснения. `shortcut` и `shortcut_label` задают повторное
открытие изученного документа, например на M.

Физическое размещение документов остаётся в `objects` файлов карт:

```json
{
  "id": "mother_letter",
  "type": "story_document",
  "position": [11.6, 1.59, 6.18],
  "size": [0.48, 0.025, 0.34],
  "selection_size": [0.58, 0.18, 0.44],
  "name": "Личное письмо",
  "style": "paper"
}
```

`id` совпадает с ID документа. Стиль `board` подходит для настенного плана.
Сюжетный персонаж в карте получает `story_actor: true`; его ID указывается в
`campaign.json` → `characters` → `entity`. Самой карте задайте `"story": "hospital"`.
Отображаемые названия персонажей и документов берутся из сценария.

## Добавить акт

1. Создайте новую папку акта: `act.json`, `dialogue.json`, `documents.json`.
2. Укажите собственные `id`, `title`, `complete_flag`, сцены, задачи и зоны.
3. Добавьте ID нового акта в `campaign.json`, установив `enabled: true`.
4. У предыдущего акта укажите `next_act` с ID нового акта; его завершение должно выполнить
   `complete_act`, затем `next_act` (можно в разных сценах).
5. Для начала нового акта добавьте в него сцену `load`.

Если следующий акт выключен, текущий остаётся активным. Сейчас включены акты 0, 1 и начало 2.
Для следующих актов добавляйте такие же папки и записи в `acts` кампании.
`entries` задаёт акт и начальные флаги при прямом запуске карты, например
`--level act1`; обычные переходы продолжают активный акт.

## Звуки и предметы акта 1

В `act.json` поле `audio_sources` содержит источники звука. `file` — путь внутри
`resources/audio`, `position` — мировые `[X,Y,Z]`, `radius` — дальность, `volume` — 0–1.
`loop: true` зацикливает звук; разрешено до трёх петель на акт. Для разовых звуков
задайте `loop: false` и `interval: [1,1]` (секунды) либо `event` (имя события).
`requires`, `unless`, `levels` работают как у сцен. Звук играет только в своём акте.
Громкость зависит от расстояния и направления взгляда; другой этаж приглушает источник.

События `locked:ID`, `opened:ID`, `collected:ID` создаются взаимодействием с замком
и ключом. `complete_act` создаёт `act_complete:ID_акта`. Сцена может ждать эти события
через триггер `event`, а источник звука — через поле `event`.

Физическая постановка третьего этажа находится в `game/levels/hospital_story.py`:
часы, телевизор, игрушка, рисунок, шкатулка, ключ и шесть камер. Литературный текст,
последовательность событий, условия появления ключа и звуки остаются в JSON.
Детская находится за внутренней дверью в северной части палаты 308. Осмотр соседних
палат необязателен: таймера, штрафов и обязательного порядка исследования нет.

## Проверить

Из корня проекта:

```powershell
.\.venv\Scripts\python.exe tools/check_story.py
```

Проверяются формат, ссылки, действия, персонажи, документы и связи с картами.
Ошибка содержит файл и поле. `--data-only` проверяет только данные,
`--story hospital` выбирает кампанию. Сценарные файлы не исполняют Python.


## Автоматические субтитры воспоминания

`voiceover` показывает автоматические субтитры по длительности `seconds`.
Старые поля `audio` и WAV сохранены как исходные данные, но игра их не
воспроизводит. Вызовы речевой озвучки удалены; голосовые пикания включены.
Обычные `dialogue` сохраняют ручное продолжение. Не добавлять синтезированную
речь обратно без прямой просьбы пользователя.

Плач — пространственная петля `crying_child`, активная после `act0:cry_started`
до `act0:cry_stopped`. Событие `opened:f2_surgery_preop` останавливает её сразу
при отпирании двери. Осмотр `f2_nursery_cradle` требует встречи с врачом,
прочтения дела, архива 1981, письма, ключа, плача и открытой двери.
`act0:complete` устанавливается после полного воспоминания и финальных пауз.
